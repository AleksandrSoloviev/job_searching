# Исследование: Трекер целевых компаний

Все пункты Technical Context закрыты. Маркеров NEEDS CLARIFICATION нет: Q1–Q3 записаны в `spec.md`. Поздний отзыв пользователя снял шифрование писем и добавил таблицу-обзор.

## Q1. Источник вакансий

- **Decision**: живого API нет. Основной путь — ручной ввод названия и URL вакансии в форме создания или правки компании. Канонический файл и импорт MAY содержать те же поля `vacancies`.
- **Rationale**: официальный ответ clarify (вариант A). GitHub Pages не проксирует чужие API; карточка без ссылок остаётся рабочей.
- **Alternatives considered**: опрос внешнего API вакансий; гибрид файл+опрос. Отклонены ответом пользователя.

## Q2. Ключевые слова фильтра

- **Decision**: только встроенный фиксированный набор в коде (`BUILTIN_FRONTEND_KEYWORDS`). Пользователь набор не видит как редактор и не дополняет. Тумблер фильтра включает/выключает применение этого набора. Совпадение — подстрока без учёта регистра в `title` и `summary`. Фильтр скрывает, не удаляет.
- **Rationale**: официальный ответ clarify («А — хардкод»). Отдельное хранилище extra-keywords нарушает FR-007.
- **Alternatives considered**: только ручной ввод слов; встроенный набор ∪ пользовательские слова. Отклонены.

Встроенный набор (константа кода, не секрет):  
`frontend`, `front-end`, `фронтенд`, `react`, `typescript`, `javascript`, `js`, `ts`, `html`, `css`, `next.js`, `nextjs`, `vue`, `angular`, `svelte`, `tailwind`.

## Q3. Публичный файл и письма

- **Decision**: публичный `public/data/companies.json` — полный снимок. `coverLetter` — обычная строка в файле, импорте, экспорте и IndexedDB. Шифрования нет. Модуля ключа, конверта и поля ввода ключа в продукте нет.
- **Rationale**: пользователь явно снял шифрование: данные только в его браузере, чувствительного содержимого нет.
- **Alternatives considered**: конверт `enc.v1` + `localStorage` ключ (прежний Q3). Отклонён.

## Таблица на главном экране

- **Decision**: таблица-обзор с колонками имя, сайт, email, вакансии. Письмо не колонкой — подсказка строки (`title` / `aria-describedby` / tooltip при наведении и фокусе). Имя выбирает компанию и открывает текущую карточку. Сайт и email — ссылки (`mailto:` для почты). Вакансии — ссылки на URL. Компактный список и `CompanyForm` остаются.
- **Rationale**: запрос пользователя: всё кликабельно, флоу редактирования сохранить.
- **Alternatives considered**: заменить список таблицей; колонка письма. Отклонены.

## Хранилище каталога

- **Decision**: IndexedDB через `idb-keyval`, ключ `job-searching:catalog`. Это единственная БД рабочей копии.
- **Rationale**: письма длинные; квота больше, чем у localStorage как БД.
- **Alternatives considered**: localStorage как основная БД каталога — отвергнут для длинных писем.

## Стек UI

- **Decision**: развивать существующий React + Vite + TS + Tailwind каркас.
- **Rationale**: уже собирается; конституция требует консистентности, не нового стека.
- **Alternatives considered**: новый фреймворк или Redux — лишняя сложность.

## Навигация

- **Decision**: один экран, без React Router. Таблица, список и карточка выбранной компании. Ручные вакансии — поля в той же форме.
- **Rationale**: десятки компаний; роутер не нужен. `404.html` остаётся на случай будущих маршрутов.
- **Alternatives considered**: отдельные маршруты `/` и `/companies/:id`.

## Сид, импорт, сброс

- **Decision**: пустой IDB → загрузить `{VITE_BASE}data/companies.json`, разобрать как файловый каталог (письмо как есть). Есть рабочая копия → сид не трогать (FR-018). Явный импорт заменяет рабочую копию целиком, если файл валиден. Явный сброс к файлу сайта — то же, что импорт текущего сида. Невалидный файл — отказ, старая копия цела. Частичный импорт запрещён.
- **Rationale**: одна схема для файла и рабочей копии.
- **Alternatives considered**: тихая перезапись при каждом деплое; сброс с мержем старых писем по id.
