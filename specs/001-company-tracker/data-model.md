# Модель данных

Канон полей — `spec.md` (модель данных + FR-012…FR-019). Здесь — правила для файла, рабочей копии и конверта письма. Значение `sKey` в этом файле отсутствует намеренно.

## Каталог

Версионированный снимок. Одна схема для файла сайта, импорта и экспорта.

| Поле | Тип | Правила |
|------|-----|---------|
| schemaVersion | string | Обязательно. Мажор `1` совместим. Иначе отказ загрузки/импорта. Текущее значение `1.0.0`. |
| companies | Company[] | Массив. Пустой допустим. Дубли `id` при разборе: последняя запись обновляет предыдущую с тем же id, в рабочей копии id уникален. |

## Компания

| Поле | Тип | Файл сайта / импорт-экспорт | Рабочая копия (IndexedDB) | Правила |
|------|-----|-----------------------------|---------------------------|---------|
| id | string | да | да | Обязателен, непустой, стабильный |
| name | string | да | да | Обязателен, непустая строка |
| website | string | да | да | Пусто или URL |
| email | string | да, открытый текст | да, открытый текст | Пусто или email |
| coverLetter | string | `""` или конверт `enc.v1…` | открытый текст (после ввода или успешной расшифровки) | см. «Письмо» |
| vacancies | Vacancy[] | да | да | Можно `[]` |
| vacanciesSource | string? | да (опц.) | да (опц.) | В v1 не запускает API |
| updatedAt | string? | да (опц.) | да (опц.) | ISO-время, если задано |

## Вакансия

| Поле | Тип | Правила |
|------|-----|---------|
| id | string | Обязателен внутри компании |
| title | string | Обязателен; участвует в фильтре |
| url | string | Обязателен в схеме файла. Без валидного URL не показывать как рабочую гиперссылку |
| publishedAt | string? | Необязательно |
| summary | string? | Участвует в фильтре |

Основной путь появления вакансии — ручной ввод `title` + `url` в форме. Файл/импорт MAY принести готовый массив.

## Письмо

### В файле (сид, импорт, экспорт)

- Пустое намерение → `coverLetter: ""`.
- Непустой открытый текст **нельзя** оставлять в файле.
- Непустой текст при записи (экспорт / подготовка сида приложением) шифруется в конверт, если `localStorage.sKey` есть.
- Если при экспорте `sKey` нет — в файл пишется `""`, пользователь видит предупреждение; рабочая копия не портится.
- При чтении файла: конверт + есть `sKey` + успешная расшифровка → открытый текст в рабочую копию. Конверт + нет ключа или ошибка расшифровки → в UI письмо пустое, конверт и «похожий на письмо» сырой текст из файла не показывают. Строка не пустая и не конверт → отказ считать её письмом, не показывать.

### В рабочей копии

- `coverLetter` — открытый текст, который пользователь видит и правит.
- Привязка строго к `id` компании (истории 2; SC-002).

### Конверт

Формат строки: `enc.v1.<salt_b64url>.<iv_b64url>.<ct_b64url>`.

- salt: 16 байт, случайные
- iv: 12 байт, случайные
- ct: AES-256-GCM от UTF-8 текста
- ключ: PBKDF2-HMAC-SHA-256(значение `sKey`, salt, 210000, 256 бит)
- AAD: UTF-8 байты `id` этой компании

Имя ключа в браузере: `sKey`. Значение — только у пользователя.

## Фильтр вакансий (не сущность хранения)

Встроенный набор — константа кода (список в [research.md](./research.md)). Не пишется в каталог и не редактируется в UI. Состояние экрана — булев флаг «фильтр включён». Совпадение: любое слово набора как подстрока без регистра в `title` или `summary`.

## Состояния каталога

- **Нет рабочей копии** → загрузить публичный сид; письма по правилам конверта; если сид недоступен — пустой каталог.
- **Есть рабочая копия** → сид не применять, пока нет явного импорта или сброса.
- **Импорт** → файл целиком валиден или отказ; при ошибке рабочая копия не меняется.
- **Сброс к файлу сайта** → разобрать текущий сид как импорт (email из файла; письма только после расшифровки).
- **Удаление компании** → запись исчезает из рабочей копии.
- **Нет `sKey`** → CRUD компаний, email и вакансии работают; письма из файла не расшифровывают и не показывают; локально введённые письма в IDB остаются видимы.

## Валидация на границе

- Неизвестные поля отбрасываются (Zod strip), загрузка совместимой схемы не ломается.
- Нет `schemaVersion`, пустой `name`/`id`, мажор ≠ 1, невалидный непустой сайт/email, вакансия без обязательных полей → отказ всего файла.
- Нехватка квоты IndexedDB → ошибка пользователю, без тихой обрезки писем.
