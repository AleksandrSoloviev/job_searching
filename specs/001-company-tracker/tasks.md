# Задачи: Трекер целевых компаний

**Вход**: документы из `/specs/001-company-tracker/`

**Предпосылки**: plan.md (обязателен), spec.md (истории), research.md, data-model.md, contracts/

**Тесты**: включены там, где план и контракт требуют проверки схемы, импорта/экспорта письма обычной строкой, фильтра и таблицы. Шифрования нет: `sKey`, `enc.v1`, `letter-crypto` в продукте быть MUST NOT.

**Организация**: фазы по пользовательским историям, чтобы каждую можно было сдать и проверить отдельно. Старый черновой `tasks.md` каноном не является. Phase 9 supersedes T001/T005/T009/T019 и прочий путь шифрования.

**Clarify (канон плана)**: Q1 — ручные ссылки вакансий, живого API нет. Q2 — фильтр только хардкод. Q3 — публичный файл полный; `coverLetter` обычная строка; шифрования нет. Таблица-обзор на главном экране, флоу формы сохранён.

## Формат: `[ID] [P?] [Story] Описание`

- **[P]**: можно параллельно (другой файл, нет зависимости от неготовой задачи)
- **[Story]**: метка истории только в фазах US; Setup / Foundational / Polish — без метки
- В описании — точный путь файла

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: без зависимостей
- **Foundational (Phase 2)**: после Setup — **блокирует все истории**
- **US1 (Phase 3, P1)**: после Foundational — MVP
- **US5 (Phase 4, P1)**: после Foundational; удобнее после US1 (общий `App.tsx`), но файл/импорт проверяется без формы
- **US2 (Phase 5, P2)**: после Foundational; нужна форма US1 и импорт US5 для пути «письмо из файла»
- **US4 (Phase 6, P2)**: после Foundational; проверка перезагрузки и сброса осмысленна, когда уже есть CRUD и письмо
- **US3 (Phase 7, P3)**: после Foundational; форма US1 уже есть — добавляются только ссылки и фильтр
- **Polish (Phase 8)**: после выбранных историй (для полного продукта — после US1–US5)

### User Story Dependencies

- **US1 (P1)**: после Phase 2, не зависит от других историй
- **US5 (P1)**: после Phase 2; UI импорта садится на список US1
- **US2 (P2)**: расширяет форму US1; расшифровка файла пересекается с US5
- **US4 (P2)**: опирается на persist из Phase 2; сброс FR-018 — только T024 (добавляет действие в `CatalogTransfer.tsx` после T017)
- **US3 (P3)**: расширяет форму US1; не требует писем для независимой проверки ссылок

### Within Each User Story

- Сначала модели/модули, потом UI, потом склейка в `App.tsx`
- Тесты истории — до или сразу вокруг модуля, который проверяют; фикстуры без пользовательского секрета
- История закрыта, затем следующая по приоритету P1 → P2 → P3

### Parallel Opportunities
